年初时我开通了 Claude Max 5x。

那段时间，我每天上班第一件事是打开 Claude Code，找找今天有什么能交给它做的。

做完份内的事，我看到额度还有剩余，就让 agent 排查代码隐患，看看有哪些地方可以优化；同时自己也看看代码，有哪些不符合要求或者设计有问题。

哪怕无事可干，我也会想“我这套开发工作流能不能优化”、“能不能写个新的 skill”、“`CLAUDE.md`{: .filepath} 中有哪些可以优化的地方”……

起初，我想用 agent 提高效率。但这个念头不知不觉变成了“还有那么多 token，不用完就亏了”。而当 token 真的用完之后，看着列表中自己生造出来的需求和任务，心里又开始发慌：额度用完了，还有这么多工作要做，这可怎么办呀……

这样一天下来，工作确实推进了不少，但下班之后脑子嗡嗡作响，工作上的念头一直萦绕在脑海中，比自己写代码还疲惫。

一段时间之后，我意识到我其实在面向 token 工作。消耗 token 从完成任务的手段变成安排工作的目标。

## 额度焦虑

我最初在工作中引入 AI agent，本意是提高效率，节省时间，好让我享受片刻闲暇，或者把精力投入更重要的事情上。但在工作上大量使用 AI agent 之后，我发现模型厂商设置的用量限制给我带来了额度焦虑。

开通会员订阅之后，我陷入一种稀缺心态，觉得自己既然花了钱，就该最大化利用订阅，榨干所有可用额度。如果没用完，我会觉得自己亏了。

和 AI 协作时，我要确定目标，用文字清晰地向 agent 传达意图，偶尔在 agent 执行的过程中介入，最终还要花时间理解、评判它的输出，提供反馈……

而且为了不浪费算力，再加上害怕错过（[fear of missing out](https://en.wikipedia.org/wiki/Fear_of_missing_out)），我生造了许多任务，堆满自己的时间表，让自己显得十分忙碌。

最后我发现，榨干算力，其实也是在榨干自己的脑力和精力。

## 被额度塑造的工作节奏

在工业时代，机器的运转时间决定工人的作息；而在 AI 时代，AI 的用量限制也在默默塑造我们的工作节奏。

大部分厂商都有五小时限额和周限额。看上去是用量限制，但换个角度想，五小时限额决定了我这五小时只能借助模型推进这么多工作，周限额也是如此。用完额度之后，我会觉得“都用完额度了，我该好好休息了”。

看似我们在役使 AI 替我们打工，但其实我们是在配合 AI 的节律活动。

## 重新找回工作节奏

在经历过年初的疯狂之后，我退订了 Claude Max 5x。最主要的原因是，我意识到我其实并不需要那么多额度，而且我也不想再让用量限制支配我的工作节奏甚至生活。

盲目忙碌之后，我才意识到闲暇的可贵。

我现在订阅两份 ChatGPT Plus，接入 [Pi](https://pi.dev) 使用。一份订阅不够，两份订阅刚好覆盖日常开发所需。我也不再盯着用量限制，根据额度来寻找任务。额度只是额度，用完就用完了，没用完也没关系。

我的任务是产出有价值的工作，而不是耗尽手上的 token。
